# Wi-Fi counter access: tools

> **Archive — not current operating instructions.** Historical documentation at [e9d71b843651](https://github.com/Protonmatter/wifi-hardware-time/commit/e9d71b84365122ff2640e240b20fc1dbb834388a). Relative links are rebased for reading. [Exact original bytes](../originals/research__tsf__README.md.txt) · [Archive index](../README.md) · [Current research](../../../docs/research-history/README.md).

These tools inspect, request and decode the Wi-Fi timing counter, called TSF. They distinguish a successful request from the later firmware report and retain action-dependent cache behavior. Private acquisition remains quarantined; offline analysis and preview are separate from explicit hardware execution and do not qualify sampling accuracy.

## Files

- [inspect_event_export_candidates.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/inspect_event_export_candidates.py): file-only CAPTUREH/QDSS route inventory and hash-pinned configuration summaries; [findings and runbook](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/firmware-trace-return-candidates.md). It sends no requests and applies no configuration.
- [export_tsf_trace_bytes.c](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/export_tsf_trace_bytes.c), [Build-TsfTraceBytes.ps1](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/Build-TsfTraceBytes.ps1) and [audit_trace_bytes.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/audit_trace_bytes.py): inspect complete selected UserData from a saved ETL, including bytes after NUL. Two saved captures contain text only in all 88 selected records; [scope and reproduction](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/saved-trace-byte-audit.md). No new capture or firmware event is obtained.
- [inspect_tsf_ingress.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/inspect_tsf_ingress.py): exact-build event registration, transport length, normalization and cleanup evidence; [runbook](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/tsf-event-ingress-and-owned-copy.md). Decoder modes `event-wire` and `htc-wire` retain the WMI event or its complete supplied transport envelope.
- The same inspector now covers the [HIF receive producer](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/hif-receive-buffer-producer.md): active callback installation, pooled-buffer reset, CE operation tables and completion handoff. Live export remains unqualified.
- Its source-validity receipt also covers pool construction/HIF binding, nonfatal MDL-allocation paths, allocation imports and the pre-header-mutation WMI boundary. These are static admission constraints, not live DMA or copy qualification.
- The [DMA backing contract](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/dma-backing-contract.md) adds selector initialization/writing, framework adapter origin, named common-buffer allocation/free slots and separate device-logical/CPU-virtual address meanings.
- The [receive-shutdown receipt](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/receive-shutdown-contract.md) adds selected disable/drain/release ordering, ignored status and conditional waits; it does not attest live callback rundown.
- [inspect_action4_completion.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/inspect_action4_completion.py) and [decode_tsf_report.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/decode_tsf_report.py): exact-build submission inspection and owned diagnostic TLV decoding; [runbook and qualification limits](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/action4-completion-and-report-contract.md).
- [decode_management_tsf.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/decode_management_tsf.py): decode peer-advertised TSF from saved ordinary beacon/probe frames; [scope and runbook](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/autonomous-management-tsf.md).
- [inspect_tsf_report_contract.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/inspect_tsf_report_contract.py): offline exact-build schema and handler field-coverage inventory; no live report decoding or device requests.
- [read_tsf_evidence.py](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/research/tsf/read_tsf_evidence.py): read saved TSF bundles; see the [API and runbook](https://github.com/Protonmatter/wifi-hardware-time/blob/e9d71b84365122ff2640e240b20fc1dbb834388a/docs/tsf/tsf-evidence-reader.md).
